# v0.2.0 — JSON入力とローカル会話キュー

2026-10-23（日本時間）。`samples/input.json` を入力に、ローカルGGUFを使って会話を生成できるリリースです。

## 追加・変更

- `setup.py/start.py/queue.py/status.py/stop.py` から準備・登録・順次生成・状態確認・終了を操作。
- `.env` でモデル・接続先・推論設定を管理し、`.env.example` を設定例として公開。
- 単一JSONの `config/characters`、`config.max_turns`、`coordinator.narration_style` に対応。
- thinking予算4096、生成全体6144を既定にし、reasoning_effortは明示しない。
- 正常終了時に終了専用Coordinatorを1回呼び、ending_narrationを生成。締めだけの失敗では会話の完了状態を保持。
- speech/thoughtの外側の装飾括弧を付けない指示を共通プロンプトへ追加。
- 入力のスナップショット、単一ワーカー、中断保存、異常終了復旧、管理対象外プロセス・コンテナの誤停止防止。
- Pythonの `chatwell.__version__` と `python -m chatwell --version` に0.2.0を追加。

## 整理

READMEを現行のLinux ARM64 / NVIDIA GB10向け手順に整理。過去の実装指示書は `docs/archive/` へ移動し、旧Windows用の導入・起動スクリプトと初回専用の成果物パッケージ作成スクリプトを削除しました。旧手順はv0.1.0タグで参照できます。

`examples/` と `templates/` は既存の直接実行・回帰テストで使うため保持。ローカルの `.env`、キュー、セッション、生応答、ログ、モデルは公開対象外で、整理に伴う削除は行いません。

## 検証と制約

- 通常の作業ディレクトリと公開対象だけを展開した隔離ディレクトリで、自動テスト56件がすべて成功。隔離環境ではsamples/input.jsonのmockによる3ターン生成と締めの保存、バージョン表示も確認。起動・停止・設定優先順位、キュー、入力上限、情報制限、終了専用生成の正常系・異常系を確認。
- Melody1437-26B-A4B Q4_K_M / GB10で、思考4096・生成全体6144の10ターンが正常完了。21回のAPI応答がすべてstop、最大生成4381トークン、約15分。この記録は終了専用生成の追加前の実装です。
- 別の入力では6ターンでgoal_achievedを確認。締め専用生成はモデル不要の自動テストで検証し、このリリース整理中の実モデル再実行は行いません。
- 会話の反復、Coordinatorの進捗評価や状況先取り、人物設定や地の文の忠実さは今後の観察対象です。
- サーバー管理は本機のLinux ARM64 / NVIDIA CDI環境向け。GUI・途中再開・履歴圧縮・自動再試行は未実装です。

実行方法は[README](../../README.md)、10ターンの測定条件は[検証報告](../validation/reasoning-budget.md)を参照してください。依頼ごとの生データはGitには含めません。
