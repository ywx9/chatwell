# v0.4.0

Chatwellを、起動済みのLLMサーバーへ接続して会話を生成する常駐HTTP APIに変更しました。Python 3.10以上の標準ライブラリだけで動作し、パッケージのインストールは不要です。

## 起動と利用

```bash
python tools/run.py
python tools/enqueue.py --input samples/input.json
```

起動中はQueueへの登録を受け付け、1件ずつ順次処理します。空なら待機し、Ctrl+Cで受付と生成を中断してアプリ全体を終了します。未着手の依頼は次回起動後に処理します。生成済みターンは保持し、中断された依頼を自動再生成しません。

`tools/run.py` は自身の配置場所からソースと既定の `.env` を見つけるため、別ディレクトリからも実行できます。シェルや実行権限の設定は不要です。`--settings`、`--data-dir` に渡す相対パスは実行時のディレクトリ基準です。

APIはローカル・信頼できるネットワーク向けで、Chatwell側の認証はありません。既定では `127.0.0.1:8090` で待ち受けます。

- `POST /v1/sessions`：登録して202とセッションIDを返します。
- `GET /v1/sessions/{id}`：状態・進捗を取得します。
- `GET /v1/sessions/{id}/result`：保存済みの結果を取得します。
- `GET /v1/sessions/{id}/turns/{index}`：指定した確定ターンだけを取得します。番号は0始まりです。
- `GET /healthz`：APIが受付可能かを確認します。

詳細は [HTTP API仕様](../http-api.md) を参照してください。

## v0.3.1からの移行

1. 更新前に旧worker・旧起動補助を停止します。LLMサーバーは利用者側で起動・停止します。
2. `.env` のLLM関連設定を次の名前へ変更します。
3. 廃止した `SELF_MANAGED_LLAMA` と `LOCAL_*`、`CHATWELL_HTTP_API_KEY`、`CHATWELL_API_MAX_TURNS`、`CHATWELL_MAX_PENDING` が残っていれば削除します。未知の設定キーはエラーになります。
4. 必要に応じて `LLM_CONTEXT_SIZE` を実際のLLMサーバーのコンテキストサイズに合わせます。既定は16384です。
5. `python tools/run.py` で起動します。旧CLIサブコマンドと `run.sh` は廃止しました。

| 旧設定 | 新設定 |
|---|---|
| `CHATWELL_ENDPOINT` | `LLM_ENDPOINT` |
| `CHATWELL_MODEL` | `LLM_MODEL` |
| `CHATWELL_API_KEY` | `LLM_API_KEY` |
| `CHATWELL_REQUEST_TIMEOUT` | `LLM_REQUEST_TIMEOUT` |
| `CHATWELL_MAX_TOKENS` | `LLM_MAX_TOKENS` |
| `CHATWELL_ENABLE_THINKING` | `LLM_ENABLE_THINKING` |
| `CHATWELL_REASONING_FORMAT` | `LLM_REASONING_FORMAT` |
| `CHATWELL_REASONING_IN_CONTENT` | `LLM_REASONING_IN_CONTENT` |

保存先は既定で `.env` のあるディレクトリ配下の `data/` です。旧保存先を使う場合は `--data-dir /path/to/old-data` で明示します。既存の保存結果は自動変換しません。LLMサーバーとChatwell APIの待受先は別です。投入スクリプトは `.env` の `CHATWELL_HOST/CHATWELL_PORT` を使います。

`pyproject.toml`、パッケージ導入用の入口、旧プロセス管理用toolsを削除しました。通常利用の入口は `tools/run.py` と `tools/enqueue.py` です。

## 生成・履歴の変更

- 初期化は最初の発言直前に留め、会話で行う依頼・了承を冒頭描写で済ませないよう指示します。
- 自身のpersona・口調・関係性をsystemに配置し、状況と履歴はuserの構造化JSONで渡します。自身のprofileは直接渡さず、他者のprofileを公開説明として使います。
- speechは原則1〜2文。必要な説明では3文以上を許し、吐息・笑い声・キスの音などの非言語音声も含められます。
- Coordinatorに未発生の返答・提案・決定を追加させず、goalを評価専用とする指示へ変更しました。
- 複数参加者では直前話者を次話者候補から除外します。明確な呼びかけ・質問先を高く推薦し、低得点の場合は発言回数に応じた重み付き抽選を行います。
- `config.llm_config.reasoning_budget_tokens` を検証し、同名でLLMへ送信します。
- 各ターン終了後の実測 `prompt_tokens > LLM_CONTEXT_SIZE - max_tokens` を条件に、未圧縮部分の古い半分を累積要約へ統合します。初回は開始状況・冒頭描写も含めます。
- 公開要約と人物別の内心要約を別々に生成し、LLMへは要約と未圧縮履歴を渡します。原文の全ターンは保存します。

保存形式は `schema_version: 1.0` を維持し、圧縮時に `conversation.compression/compressions` を追加します。APIの結果は公開用の投影で、保存JSON全体とは異なります。詳細は [入出力仕様](../input-output.md) を参照してください。

## サンプルと検証

[samples/input.json](../../samples/input.json) はそのまま実行し、カスタマイズできる入力例です。[samples/output.json](../../samples/output.json) はその入力による11ターン・goal_achievedの保存結果で、保存時のバージョン表記は0.3.1です。履歴圧縮は発生していない実行記録で、内容は変更していません。

ローカルではLinux/Python 3.12で73件のテストが成功しています。内容はAPI・投入・起動・Ctrl+C中断・再起動・保存・累積圧縮と情報境界です。v0.4.0としての新規の実モデル検証、圧縮後の要約品質の実モデル検証は未実施です。

CIはLinux・macOS・WindowsのPython 3.10/3.13を対象にします。実プロセスへのSIGINT送信を使う終了テストはLinux/macOSが対象です。ほかのOS・Pythonの実行結果はCIで確認します。
