# v0.1.0 — CHATWELL initial prototype

> 以下は初回リリース時の記録です。Windows用スクリプトと初回成果物パッケージ用スクリプトはv0.2.0で削除しました。当時の手順は `v0.1.0` タグのソースで参照・実行してください。

ローカルGGUFとllama.cppを使い、キャラクター同士の複数ターン会話を生成する初回プロトタイプです。

- Coordinatorの初期化・毎ターン更新、推薦と発言回数による次話者選択。
- キャラクター向け入力からgoal・他者のthoughtを除外。
- 原文とCoordinator改稿版を単一セッションJSONへ逐次保存。
- 目標達成・ターン上限による停止、途中失敗時の結果保持。

検証は[初回](../validation/initial.md)と[複数ターン](../validation/multiturn.md)を参照してください。21件の自動テストと、Gemma-4-E2B-it Q4_K_Mの実モデル4ターン生成を確認しています。実モデルの状況要約には初期文を繰り返す課題が残ります。26B・GPU検証は行っていません。

## 添付する検証成果物

- `validation-initial.zip`: 過去のセッション、生API応答、サーバーログ、直近の自動テスト結果、manifest。
- `validation-initial.zip.sha256`: ZIPのSHA256。

生データはmainの履歴には含めません。ZIP内のローカルユーザーパスは`<USER_HOME>`、ワークスペースは`<WORKSPACE>`へ置換しています。ローカル原本は変更しません。manifestには原本とZIP内ファイルの両方のSHA256を記録します。

過去の実モデル出力は初回コミット以前の各実装段階で生成した記録です。manifestのsource_commitはパッケージ作成時のコードを示し、過去の全出力がそのコミットで再生成されたことを意味しません。

## パッケージ作成

初回コミット後、ワークスペース直下で実行します。

```powershell
python -m unittest discover -s tests -v 2>&1 | Tee-Object -FilePath .local-artifacts/unit-tests.txt
python scripts/package_validation.py --test-log .local-artifacts/unit-tests.txt
```

`.local-artifacts/`はGit管理対象外です。作成スクリプトが対象ディレクトリを作成します。上のテストログを先に保存する場合は`New-Item -ItemType Directory -Force .local-artifacts`で作成してください。
