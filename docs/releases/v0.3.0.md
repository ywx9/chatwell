# v0.3.0

任意のllama.cppサーバーを利用するCLIへ整理しました。会話品質や会話生成ロジックの変更を目的とするリリースではありません。

## 変更

- 特定のOS・CPU・GPU・Dockerに依存する推論サーバー管理を削除。サーバーの導入・起動・停止はユーザーが管理。
- HTTP(S)のローカル／リモートサーバー、Bearer認証、サーバー側モデルIDに対応。
- `chatwell run/doctor/enqueue/worker/status` に入口を統一。直接実行とキューで統合JSON入力と共通設定を使用。
- Gemma 4系を推奨。実際の対応はllama.cpp・モデル・設定で診断。
- 公開例を `samples/input.json` に集約。旧分割入力とテンプレートはテスト専用fixtureへ移動。
- Pythonパッケージ、Windows/macOS/Linux向けCI、CLI・設定・認証・排他制御のテストを追加。

## v0.2.0からの移行

**更新前に旧環境で** `python3 scripts/stop.py` を実行し、旧workerと管理コンテナを停止してください。既存の設定・モデル・生成結果は保存してください。v0.3.0には旧管理スクリプトがありません。

| 旧操作 | 新操作 |
|---|---|
| `scripts/setup.py` | llama.cppを環境に応じて用意し、`chatwell doctor` |
| `scripts/start.py` | llama.cppは別途起動。キューには `chatwell worker` |
| `scripts/queue.py --input ...` | `chatwell enqueue --input ...` |
| `scripts/status.py` | `chatwell status`（依頼件数のみ） |
| `scripts/stop.py` | worker端末でCtrl+C。llama.cppは別途停止 |
| `python -m chatwell --config ... --characters ...` | `chatwell run --input samples/input.json` |

旧 `.env` はそのまま `--settings` に指定しないでください。v0.3.0は未知のキーを拒否します。`.env.example` を参考に別ファイルを作り、必要な項目を移してください。自動上書き・自動移行は行いません。

- `CHATWELL_MODEL` はGGUFパスから **サーバー側モデルID／alias** に意味が変わりました。通常は未指定でも構いません。
- `CHATWELL_PORT` は `CHATWELL_ENDPOINT` へ変更。`CHATWELL_CONTEXT_SIZE/GPU_LAYERS/START_TIMEOUT/REASONING_BUDGET` はChatwellでは管理しません。必要なものはllama.cpp側へ設定してください。
- `.env` は自動読込せず `--settings` で指定します。環境変数は従来どおり利用可能です。
- workerは常駐バックグラウンド起動からフォアグラウンド実行へ変更。複数端末から同じdata-dirを指定します。停止はCtrl+Cです。
- 既存のセッションや依頼JSONは書換えません。旧キューを使う場合はリポジトリ直下をdata-dirにし、旧worker停止後に開始してください。待機依頼は新workerの接続・生成設定で処理されます。

## 検証と制限

Linux x86_64 / Python 3.12でユニット・CLIテスト、HTTPテストサーバーで認証・構造化応答、パッケージ導入、モック会話を検証。Windows/macOSの実行結果はCIで確認します。Gemma 4の実モデルによる再検証・`samples/output.json` は利用者側で実施予定です。このリリースに生成例の捏造や未検証の互換性保証は含めません。
